# W6: graph value under the default ranker

Owns (see `COVERAGE.md`): C1-5, X-1 (ADR-004 storage roles).

Wave C, after W1 (W6 measures on W1's temporal retrieval) and P8 (live
Neo4j, Qdrant and pgvector at scale).

## Question

Does the knowledge graph earn its place in retrieval? The shipped `hybrid`
ranker does not use the graph at all: `memory_ranking.py` ~33-47 says so,
while `ARCHITECTURE.md` and the V2 delta table still claim graph relations
are loaded in V2 (C1-5). Personalised PageRank scoring existed only under
`actr_v1`.

Pre-registered rule (`05-research-plan.md`): a `hybrid+ppr` arm on lifesim's
multi-hop and causal probes against live Neo4j. If the gain is under 0.05
(absolute, on the primary metric), the graph stays for its other roles only,
and ADR-004 says so.

## Deliverables

1. **A `hybrid+ppr` arm** behind switchboard flag `MEMORY_GRAPH_PPR_ENABLED`
   (BrainBench arm `+graph`). It adds a graph term to the hybrid ranker:
   PPR from the query's entities over the entity graph, with the weight
   tuned on tune seeds only and frozen before the dev-panel comparison.
   Graph access must fit the interactive budget (DR-024); state the added
   latency at P8's sizes.
2. **The measurement.**
   - Memory suite `llm_augmented`, 12-persona panel. Primary metric:
     hit@3 on `multi_hop` + causal probes. Also every other category, to
     catch regressions.
   - `compare` baseline vs `+graph`, with Holm across memory categories.
   - Also a live-Neo4j run at a P8 size, to show the effect survives scale.
3. **ADR-004, storage roles.** For each store (SQLite index, pgvector,
   Qdrant, Neo4j, Redis working memory), state:
   - its unique cognitive value, measured (from P8 and this workstream)
   - what would break without it
   - the decision: keep as is, keep for a narrower role, or remove

   No store is removed on one benchmark: removal needs P8's numbers and this
   one agreeing.
4. **C1-5**: correct `ARCHITECTURE.md`'s graph claim and the V2 delta
   table to match the code, as shipped after W6. `test_doc_drift.py` must
   pass.

## Acceptance (mechanical)

- The pre-registered rule is applied unchanged:
  - multi-hop/causal hit@3 gain >= 0.05, significant after Holm, and no
    significant regression in any other category: `+graph` is adopted.
  - Otherwise it stays off, the ADR records the null result with its
    confidence interval, and the arm stays in the switchboard for later
    re-testing.
- Added P95 retrieval latency with the graph term fits DR-024 at P8's 100k
  size.
- `tests/test_brainbench_gates.py` passes.
