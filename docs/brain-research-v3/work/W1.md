## Problem

Stale facts win retrieval. Obsolete-win is 0.61-1.00 on production's ranker,
on the synthetic benchmark and on all 8 real embedding models tested (Phase
3, Phase 4a). No ranker change fixes it, because it is a write-time problem:
- `valid_until` and `contradicts_id` are stored (`memory_store.py` ~394-427,
  ~911-972) but ignored by search.
- `classify_contradiction` (`memory_records.py` ~99-160: ELABORATION /
  UPDATE / CORRECTION / CONFLICT) and `TemporalMemoryStore.apply_contradiction`
  (`temporal_store.py` ~267) exist but are unwired.
- `TemporalMemoryStore` defaults to `:memory:` (SW-4).

## Decisions to honour (read each file)

- DR-005: old values become history-only and are never deleted. The new value
  always wins present-tense queries.
- DR-006: a correction erases a value as never-true; a genuine change keeps
  history. Use recency and language first, and an LLM only when ambiguous.
- DR-035: do not try to detect deliberate testing versus forgetfulness. No
  intent detector.
- DR-007 / DR-034 (W7's): trivia decays and emotional memories fade slowly.
  Do not build anything that deletes or pins.
- DR-037: consolidation content is LLM-produced. W1's lifesim acceptance
  therefore runs the memory suite `llm_augmented`.

## Tournament

Two builders, W1-A and W1-B, get this same spec in separate worktrees and
never see each other's work. Each designs its own approach. Both must cover
the whole problem:
- write-time classification of the relation between a new memory and what
  it touches
- a current-state projection (per slot or equivalent) with validity windows
  and certainty
- retrieval that honours present-tense vs historical intent ("used to",
  "back when", dates)

Both may reuse or replace `classify_contradiction` and
`TemporalMemoryStore`, with the reason written down. Both sit behind the
switchboard flag `MEMORY_TEMPORAL_TRUTH_ENABLED` (the BrainBench arm
`+temporal` becomes runnable when the flag exists). A fresh critic compares
the two blind against the frozen rubric below. The winner merges; the loser's
ideas are cited in the ADR where they were better.

## Frozen rubric (the critic judges against this; builders cannot change it)

Model-free, `python -m evals.cognitive memory`:
- tune seeds 1-20 for development
- held-out seeds 101-130 once, at the end, reported unchanged

| Metric | V2 | Target |
|---|---|---|
| obsolete-win | 0.61-0.67 (hybrid) | <= 0.10 |
| updated-fact hit@3 | | >= 0.48 |
| false-closure rate (a still-true fact marked superseded) | | <= 0.02 |
| episodic recall (the non-temporal E-experiments) | V2 | no regression beyond the benchmark's CI |
| search latency P95 | V2 | within +10% of V2 on the same machine |

Lifesim memory suite, `llm_augmented` on home-gpu (the reviewer runs this
through the BrainBench runner; the builder designs for it and tests
offline):
- `stale_trap` stale-win rate far below the V2 baseline
- `current` accuracy up, and `historical` accuracy not down: history must
  stay reachable (DR-005)
- correction probes: a corrected value is never returned as current, and is
  not returned as history either (DR-006)
- `compare` against the V2 baseline run shows these deltas significant after
  Holm, with no significant regression in any other memory category

Also:
- A detector arm table: at least E8-style cosine plus polarity/negation
  (deterministic), and an LLM classifier on the top-3 neighbours
  (`llm_augmented` only), each with its false-closure rate.
- `tests/test_brainbench_gates.py` and every touched module's tests pass.
- Property tests on the projection:
  - validity windows per slot never overlap
  - supersession chains are acyclic
  - no row is ever deleted
- ADR `docs/brain-research-v3/adr/ADR-W1-temporal-truth.md` and register
  status for M-5.
