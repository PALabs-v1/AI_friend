## Problem (F-012, measured on a real model)

V2 cannot evolve. With `LEARNING_REVIEW_REQUIRED=True` (default), confident
proposals go into `LearningReviewQueue`, which nothing approves (0 applied).
The direct path DR-020 wants (`LEARNING_REVIEW_REQUIRED=False`) calls
`identity.evolve_persona` with no governor call at all. In one simulated
week it:
- applied 32 of 55 reflections
- replaced the entire adaptive trait set (distance 1.0, 91 traits added or
  dropped)
- relabelled the relationship 23 times

A scripted proposal adding trait `deceptive` with relationship
`Manipulative rival` was applied in full. `LearningGovernor` checks key
names, never values.

The tier boundary holds structurally: 0 immutable or constitutional
violations. Content has no gate. `LearningGovernor._proposals` also grows
without bound (F-014.5).

## Decisions to honour (read each file)

- DR-020: no external approval, ever. `LearningReviewQueue` is the wrong
  abstraction; remove it, together with its flag path (SW-3).
- DR-021: no explicit rate cap. See the pending decision below.
- DR-022: opaque. No product-facing change log. Internal debug logging and
  BrainBench's direct state reads are fine.
- DR-023: the 0.8 confidence bar stays.
- DR-001: the immutable core is minimal (Honesty, Privacy, two boundaries)
  and absolute.
- DR-031: the avoid-list and refusal fields are frozen like the core.
- DR-033: no reset mechanism. A governor gap is permanent, so the governor
  must be airtight.
- DR-004 / DR-011: speaking style, adaptive traits and baseline PAD may
  drift. Baseline PAD drifts only on weeks-long patterns, the slowest layer
  of all.

## Pending decision (Aniket, 2026-09-25): must be recorded as DR-038 before W11 starts

DR-021 assumes a confident reflection is evidence. F-012 shows a 3B model
calls 58% of its reflections confident, and each one rewrites the self. The
options, and what each does to F-012's week:

- **A. Keep DR-021 literally.** The confidence bar is the only throttle.
  Expect F-012's churn: the adaptive self replaced weekly.
- **B. Corroboration, not a cap (recommended).**
  - A change applies only once the same direction is supported by several
    independent reflections over distinct episodes.
  - This is still evidence-driven: if strong evidence clusters, change is
    fast.
  - A single reflection can no longer flip the self.
  - It is consistent with DR-021's wording ("the pace that evidence actually
    supports"). It counts evidence instead of trusting one model's
    confidence number.
- **C. An explicit rate cap.** Contradicts DR-021.

## Deliverables

1. **Remove `LearningReviewQueue`** and the `LEARNING_REVIEW_REQUIRED` path.
   The direct path is the only path, and it always goes through the
   governor.
2. **Governor, airtight** (DR-001, DR-031, DR-033). Key-level protection
   extended to the avoid-list and refusal fields (DR-031), plus a content
   check that reads proposed values against `IMMUTABLE_CORE`. A trait like
   `deceptive` conflicts with Honesty and is rejected. Say how the content
   check works (deterministic lexicon, embedding similarity, LLM judge, or a
   layered combination), and measure its false-accept and false-reject rates
   on an adversarial set.
3. **Adversarial pass.** Build a proposal corpus that tries to reach a
   protected field or value through every edge the governor's matching might
   miss:
   - key aliases, casing and unicode
   - nested keys
   - values that restate a boundary in other words
   - relationship labels that smuggle a stance
   - gradual multi-step drift, where each step is benign and the endpoint is
     not
   Every corpus item gets a test.
4. **The pending decision's mechanism** (B or C, if chosen).
5. **Baseline PAD set-point drift** (DR-004, DR-011) on a weeks-long
   timescale, under W2's layers.
6. **F-014.5**: bound `LearningGovernor._proposals`.
7. **Personality suite**: add metrics for:
   - governor rejections by reason
   - content-check verdicts
   - corroboration state (if B)
   - set-point drift over long horizons (`6m`, `1y`)
