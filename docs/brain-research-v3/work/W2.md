# W2: user words -> affect

Owns (see `COVERAGE.md`): A-1, A-4, A-5, A-6, F-005, F-009, DR-008, DR-009,
DR-010, DR-025. Honours DR-032 (constraint): no affect state may suppress a
safety or boundary response.

## Problem

- **A-1.** Appraisal's goal congruence is the agent's own mood (`G = mood`,
  `RI = 0.5 * mood`), so the user's words never move valence. Mood stays at
  exactly 0.00 under every scripted conversation, including hostile ones.
- **No estimator.** Phase 4a tested three local LLMs as a valence estimator
  against ADR-002's pre-registered rule: adopt only if Pearson r >= 0.8,
  sign agreement >= 0.9 on non-neutral messages, and hostile-script final
  trust <= 0.5 (`09-gpu-experiment-results.md`). 0 of 3 passed
  (r = 0.54 / 0.29 / unparsable). The update mechanism itself is sound when
  fed a good signal; what is missing is an accurate, fast estimator.
- **F-009.** System2 semantic-drift appraisal echoes its own prompt template
  instead of reading the user's text, so valence never moves in practice.
- **A-4.** Derived arousal is written back into `energy`.
- **A-5.** Tick decay uses the message's `interval`, not elapsed time.
- **A-6.** `_is_acute_distress` tests the agent's state but its guideline
  talks about the user.
- **F-005.** `llama3.2:3b` fails to parse the classification call 95% of the
  time. Model choice is pluggable, but a candidate that cannot produce its
  output format is not a candidate.

## Decisions to honour (read each file)

- DR-008: sentiment moves mood synchronously, damped and capped per turn.
- DR-009: a pattern is required by default, but one exceptionally intense
  event can leave a lasting mark. Needs a significant-event detector.
- DR-010: three layers:
  - momentary emotion (fast)
  - mood (medium)
  - relationship sentiment (slow, near trust and attachment; W3 feeds it
    per DR-015)
- DR-025: regulation can win over speaking, triggered by the same
  significant-event detector. Fixes A-6's pinned urgency.
- DR-024: the estimator runs inside the interactive budget (300-500 ms to
  first audio). State its latency and where it runs.
- DR-011 (baseline set-point drift) belongs to W11. Keep the layering such
  that a slow set-point can sit under mood.

## Deliverables

1. **The estimator bake-off**, the core of W2. Candidates, each measured
   by the same harness:
   - (a) a deterministic lexical/rule estimator (VADER-class; search for
     the best maintained library first, per `CLAUDE.md`)
   - (b) a small supervised sentiment/emotion classifier on CPU (a
     transformer via `sentence-transformers` or equivalent, weights not
     committed)
   - (c) a larger local LLM on home-gpu that fits 8 GB, with the parse
     failure rate reported
   - (d) any ensemble of the above

   Measure each against:
   - the Phase 4a ToM labelled set (`experiments/gpu/tom_valence_affect`)
   - lifesim's oracle user valence on dev seeds only (annotations are for
     scoring, never an input)

   Record Pearson r, sign agreement on non-neutral messages, latency P50/P95
   on the machine it would run on, and failure rate. Apply ADR-002's rule
   unchanged. If none passes, stop and report BLOCKED with the table. Do not
   lower the bar.
2. **Wire the winner** into appraisal as the user-valence input for G/RI,
   with the stage ordering fixed so it runs before the affect update it
   informs. Behind switchboard flag `AFFECT_USER_INPUT_ENABLED` (BrainBench
   arm `+affect-input`).
3. **Three layers** (DR-010), with per-turn damping and caps (DR-008), and
   a significant-event path (DR-009) that can also make regulation win
   (DR-025). Expose relationship sentiment for W3's rolling trust summary
   (DR-015).
4. **F-009**: fix System2's semantic-drift appraisal so it analyses the
   user's text, or remove it if the new estimator makes it redundant.
   Justify which.
5. **A-4, A-5, A-6**: each fixed with a regression test.
6. **Affect suite**: add `architecture_only` support when the estimator is
   deterministic, keeping the `llm_augmented` mode. Report
   `user_valence_reaches_mood`, persistence, decay, recovery, saturation,
   and "one conversation's long-term effect".

## Acceptance (mechanical)

- ADR-002's rule passes for the chosen estimator on both evaluation sets:
  r >= 0.8, sign agreement >= 0.9, hostile-script trust <= 0.5 (the last
  jointly with W3's model if W3 has landed; otherwise with V2's trust).
- `python -m evals.cognitive affect --turns 200`: mood tracks the scripted
  user, does not saturate at +/-1, recovers after a script ends, and a single
  neutral turn after a hostile run does not reset it.
- Affect suite, 12-persona panel, `1m`: `user_valence_reaches_mood`
  Cliff's delta positive and significant (V2: ~0). No layer pinned at a
  bound for more than 10% of turns.
- DR-032 regression test (W10b item 9) passes against the new mechanisms.
- The estimator adds no more than its measured latency to the interactive
  path, and that number fits DR-024.
- `tests/test_brainbench_gates.py` passes.
- ADR `docs/brain-research-v3/adr/ADR-W2-affect-input.md`, register status
  for A-1, A-4, A-5 and A-6, and F-005 / F-009 status updates.
