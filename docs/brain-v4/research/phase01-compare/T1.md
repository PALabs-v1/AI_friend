## 1. Agreements across all three

1. Neither owner frame is enough alone; the state/timescale view beats both. Codex: "state-transition graph with temporal lanes". AGY: "multi-timescale heterarchy with global working state". Claude: "state ledger with tiers and loops as edges". Same core idea, three names: one typed state, several timescales, identity as slow rows plus constraints, not a layer.
2. Frame A (layers) hides arbitration, state ownership and the downward write. Frame B (loop) hides concurrent and background work and multiple rates. All three say this in different words.
3. Closed means a write path, a read path, and an intervention on the state changing later behavior. Codex has five conditions, Claude five (a to e), AGY three couplings plus do(S_t). All propose clamp/swap/ablation. All say consciousness is UNKNOWABLE.
4. Mood appraisal is not driven by user text on the sync path. `pipeline.py:817` `emotional_bias = state_snapshot.get("mood", 0.0)`. VERIFIED in code.
5. Persona drift dead-ends by default. `config.py:278 LEARNING_REVIEW_REQUIRED=True`, `learning.py:367-374` submits to `review_queue`; grep shows no production caller of `LearningReviewQueue.approve`. VERIFIED. (`learning.py:435 governor.approve` is a separate LOW-risk safety filter, not the queue.)
6. Monologue is published to `state.subconscious` with no subscriber; dream text is log-only. `subconscious_agent.py:773-776`, `836-840`; repo's own `scripts/check_subject_wiring.py:96` says "zero subscribers". VERIFIED.
7. `TemporalMemoryStore.apply_contradiction` has no runtime caller (`temporal_store.py:267`). VERIFIED.
8. "Workspace" in code is a per-turn CAS store, not competition and broadcast (NF-38).

## 6. Decisions this track forces on Aniket

1. What counts as "closed" for V4 claims?
   (a) Intervention on the external state ledger changes a pre-registered behavior metric (works with Claude Code and any model).
   (b) Also require internal-activation intervention (open-weight models only, GPU box).
   (c) Both, reported separately.
   Recommend (a) as the gate, (c) as optional research. Ledger interventions are exact API calls and answer "how would anyone tell" now.

2. Working vocabulary for V4: three layers, the loop, or something else?
   (a) State ledger with latency tiers and loops as edges (Claude, Codex-compatible).
   (b) Keep the owner's three-layer words for explanation, ledger for engineering.
   (c) Adopt a global-workspace heterarchy (AGY).
   Recommend (b): tier names kept for talking, ledger as the checked artifact. Reject (c); no evidence it helps here (NF-38).

3. Fate of non-consumed outputs (monologue, dream, calibration, plan_verifier, simulation).
   (a) Delete them.
   (b) Feed them as provenance-tagged candidates into initiation, with a pre-registered ablation, delete if no effect.
   (c) Leave log-only.
   Recommend (b) for monologue/dream with a deadline, (a) for the dead plan/calibration code unless V4 names a deliberative use. Needs Invariant 12 decision.

4. Persona self-change gate (DR-020 says no external approval; code requires it by default).
   (a) Auto-commit after N corroborating reflections on separate days, bounded to ADAPTIVE fields.
   (b) Keep the queue and add an approver.
   (c) Freeze persona drift in V4.
   Recommend (a); it matches DR-020/DR-038. N and thresholds should come from a lifesim sweep, not from AGY's guesses.

5. Experiment snapshots vs DR-033 (no reset by design).
   (a) Allow developer-only snapshot/restore for BrainBench transplant tests.
   (b) Forbid; test only by fresh-start replay.
   Recommend (a), never product-facing. Needed for state-swap trials.

6. Do the V3 stale-doc claims get corrected before Phase 02? Two reports inherited a false "completion signal never emitted". Recommend a quick doc-drift fix to `00-current-architecture.md:88` and a re-check of any other V3 doc statement before V4 design uses it.
